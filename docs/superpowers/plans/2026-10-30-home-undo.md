# Homepage undo implementation plan

> **For agentic workers:** Use superpowers:executing-plans to implement the checked steps inline.

**Goal:** Add Ctrl+Z for saved GTD actions without adding controls or replacing text-editor undo.

**Architecture:** An in-memory, bounded transaction history serializes plugin mutations. Exact before/after content is captured inside Vault.process. Undo validates identity, path and current content before restoring. Multi-note moves undo together and compensate an interrupted undo without overwriting subsequent edits. Project metadata uses the same atomic content boundary. File renames and project order use guarded inverse operations.

**Tech Stack:** Existing Obsidian API, JavaScript/CJS, Node test runner; no new dependency.

**Spec:** User accepted Ctrl+Z for homepage operations; native text undo takes priority, no new buttons, short result notice. Existing same-level drag and ephemeral drafts remain unchanged.

## Global constraints

- Preserve task metadata, hierarchy, source line endings and foreign edits.
- Keep up to 30 transactions in this plugin session; no persistent history.
- Support task add, completion, rename, dates, deletion, restore, ordering and inbox moves; project rename, deadline, completion and archive.
- New project/area creation is a history boundary; it clears earlier undo instead of deleting newly created notes through a shortcut.
- Ctrl+Z is handled only in a rendered GTD page, outside editable text/date/select controls and dialogs. Shift+Ctrl+Z is untouched.

## Review focus

- Input/IME shortcuts must remain native.
- Multi-note undo must preflight all files before writing.
- Writes beginning concurrently must have deterministic history order.
- Failed/no-op writes must not create misleading history entries.
- A recreated file with the same path must never receive an older undo.
